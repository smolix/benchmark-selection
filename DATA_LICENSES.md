# Data licenses and provenance

This repository contains **code** and **derived benchmark score tables**.

- **Code** (`code/`, `data/*.py`, `data/*.sh`, `paper_tools/*.py`) is released under the Apache License 2.0 (see `LICENSE`).
- **Data files** (`data/*.csv`, `data/*.npz`, `data/*.json`) contain numeric scores that public leaderboards
  published for language and embedding models, plus metadata (revisions, checksums, dates, evaluation costs).
  They contain **no benchmark questions, reference answers or prompts, and no text generated by models**. The
  only item-level file, `olv1items.items.npz`, stores per-item correctness derived from model outputs (0/1;
  mc2 scores in [0, 1] for TruthfulQA), indexed by position, without item text.
- Each data file **remains subject to the terms of its upstream source**, listed below. We claim no rights
  over upstream data. Several sources declare no license at all (marked "none declared"); for those we
  redistribute the published scores for research use, attribute the source, and will remove files on request.
- Our own contributions (the canonical model-name mapping `canonical_mapping.json`, the metadata we authored in
  `*.meta.json`, `raw_manifests/`, `score_bounds.json`, `SHA256SUMS`, the cost tables, our arrangement of the derived
  matrices, and every output of our code in `results/` and `paper_tools/*.csv`) are released under
  **CC BY 4.0** (see `LICENSE-DATA`). This does not relicense the upstream scores inside those files.
- **Removal on request.** For sources that declare no license we redistribute derived numeric scores for research
  use with attribution, and we remove any file on request. Contact for questions or takedown requests:
  **alex@smola.org**.
- **Non-commercial data.** The AlpacaEval scores (`alpaca_eval.*` and the three `alpaca_eval/*` columns of
  `merged.matrix.*` and `merged_v1.matrix.*`) are shipped under **CC BY-NC 4.0**: attribution, non-commercial use
  only, changes indicated (section 3.3). Drop those three columns for commercial use.
- **Not shipped:** BenchPress (`benchpress.json`, `benchpress.matrix.npz`): fetch it with
  `data/download_benchpress.py`, which pins the upstream commit and checks the SHA-256 (section 2.6). Epoch AI: only
  the 15 columns that come from Epoch's own benchmark files are shipped (`epoch_own.*`); the full 61-column matrix used
  in the paper is rebuilt with `data/build_epoch.py` (section 2.7).

All dates are UTC unless marked otherwise. "Equals revision X" means the file was fetched from the default
branch without a pin and all of its values equal those at revision X (checked 2026-10-18).

## 2. Upstream licenses in detail (checked 2026-10-18)

### 2.1 Hugging Face datasets without a declared license
`open-llm-leaderboard-old/results`, `open-llm-leaderboard/results`, `open-llm-leaderboard/contents`,

the Hub's services*; the terms do not by themselves license redistribution elsewhere. We redistribute only
derived numeric scores, with attribution, and remove files on request (alex@smola.org).

### 2.2 HELM (Stanford CRFM)
The [HELM repository](https://github.com/stanford-crfm/helm) is Apache-2.0. We found no license or terms of use
for the published results (`benchmark_output` files in the `crfm-helm-public` bucket, or the leaderboards at
<https://crfm.stanford.edu/helm/>). HELM entered maintenance mode on 2026-06-01. We redistribute derived numeric scores with attribution to HELM.

### 2.3 AlpacaEval

AlpacaEval scores, including the three `alpaca_eval/*` columns of `merged.matrix.*`, as **CC BY-NC 4.0**

### 2.4 MT-Bench judgments
`SUSTech/mt_bench_judge` has no description and no license. Its 800 rows (5 models x 80 questions x 2 turns, GPT-4
judge) are copies of rows of LMSYS's pre-generated GPT-4 single-answer judgments for the MT-Bench paper
(`data/mt_bench/model_judgment/gpt-4_single.jsonl`, 34 models): score, judge and judgment text agree in all 800
rows, and all 40 cells of `mt_bench.csv` equal the per-(model, category) means computed from the LMSYS file. That
file is not part of the Apache-2.0 [FastChat](https://github.com/lm-sys/FastChat) repository: FastChat's
`fastchat/llm_judge/download_mt_bench_pregenerated.py` fetches it from the
[HF Space `lmsys/mt-bench`](https://huggingface.co/spaces/lmsys/mt-bench) (revision
`a4b674ca573c24143824ac7f60d9173e7081e37d`), whose card declares `license: other` and states no terms.
Section 2.1 applies.

## 5. Known caveats

- `open_llm.csv` (fixed 2026-10-18) vs. `open_llm_v1.csv` (submission): the original downloader
  (`download_open_llm.py` before 2026-10-18) kept each model's last result file in path order and, when a group
  entry was blank, matched result keys by substring, storing the first sub-task's score as the group score. The
  rebuild changes 200 cells in 47 of the 4,507 rows (180 values and 20 previously missing cells; one further cell differs
  by 1 ulp). By cause, counting the cells read from a different file (210 in total):
  22 rows with sub-task scores stored as the BBH, GPQA and MuSR aggregates (66 misread cells; 68 cells change in
  these rows because one of them also gets a different file); 20 rows where another complete run was kept, read
  correctly but not the run the leaderboard shows (114 cells); 5 rows read from partial BBH + MATH re-uploads
  (28 cells, 20 of them missing in v1). The 14 rows the leaderboard table cannot place keep their v1 values.
  `olv2sub.meta.json` (`consistency_checks.vs_open_llm_csv.disagreement_causes`) lists the affected rows.
  Only 2 of the 47 rows are in `merged.matrix.*` (`HuggingFaceH4/zephyr-7b-alpha`, `google/gemma-7b-it`, both
  partial re-uploads): 8 cells change (missing to observed) and the observed cells go from 4,185 (`merged_v1`) to 4,193.
- `mmlu.csv` (frozen) reads only the last results file of each model directory, so re-evaluated models show their
  last run, and 1,640 models whose MMLU results are only in earlier files are missing (1,639 whose last file has no
  MMLU, 1 whose last file has too few subjects for the 50% coverage filter of `build_matrices.py`).
  `download_mmlu.py --recover-earlier-files` adds them. The frozen files were also downloaded to a
  case-insensitive (macOS) file system, which merged 18 model directories whose names differ only in case: 16
  models were lost, `aihub-app/zyte-1.1b` was filled from the merged pair's last file (max |diff| 0.119), and 22
  names took the other casing. On a case-sensitive copy the default rule gives 5,470 / 5,468 rows instead of
  5,454 / 5,452; emulating the merge reproduces the frozen `mmlu.csv` bit for bit.
- `helm.csv` column "Mean win rate" is HELM's ranking statistic (it depends on the set of models), not a
  benchmark score; it is a column of `merged.matrix.*`.
- `livebench.*` has 3 of LiveBench's 6 categories, the ones present in `livebench/model_judgment`.
- `bigcode.*` holds BigCodeBench per-domain solve rates (not HumanEval/MBPP or EvalPlus scores).
- `mt_bench.*` covers 5 models; in `merged.matrix.*` its 8 columns are observed for 3 models.
- BenchPress (`benchpress.json`, downloaded) collects scores from heterogeneous public reports with different evaluation settings.
- `olv2sub`: MATH-hard sub-tasks were scored with three scorer versions (3.0: 3,702 models; 2.0: 777; 1.0: 14).
- `olv1items`: TruthfulQA items are continuous mc2 scores, not 0/1; the 395 models are the tinyBenchmarks
  selection of leaderboard models evaluated 2023-07 to 2024-01.
- `helm_classic`: few-shot runs only; 19 cells differ from the HELM website, which pools zero-shot ablation runs
  into them (HELM's values are kept in the metadata).
- `epoch`: rows merge model versions (snapshots, reasoning-effort variants) into one model group; values are the
  best variant, rescaled between random baseline and ceiling.
- `mteb2026`: 17 snapshot models appear under new names (`snapshot_name` joins them), 2 new rows reuse result
  files of snapshot models, and release dates are supplied by model authors.
